# 使用指南 (Documentation)

---

## ⚙️ 配置 (Configuration)

### 步骤 1：选择服务（一级界面）

> 集成安装方法见 [README](../README.md#-安装)。

- **服务**：下拉选择 **昆仑燃气**、**油价信息**、**每日内容** 或 **灾害预警**。
- 每个服务**只允许一个条目**：若该服务已添加，选择后会直接提示「该服务已添加」，不再进入二级表单。要增加户号 / 省份请走条目选项（见下文）。

### 步骤 2：填写接入信息（二级界面）

#### 昆仑燃气

| 字段 | 说明 |
| :--- | :--- |
| **接入名称** | 选填，作为设备名称，留空自动填 `户号:<户号>`。 |
| **户号** | 燃气缴费户号，提交时校验接口是否返回该户号。 |
| **所在地区** | 下拉选择省份/地区，提交时与户号一并做连通性预检。 |

- 三级字段同页提交，配置时即验证户号与地区匹配、接口可达。

#### 油价信息

| 字段 | 说明 |
| :--- | :--- |
| **接入名称** | 选填，作为设备名称，留空用省份名（如 `北京`）。 |
| **ApiZero KEY（选填）** | ApiZero 密钥。留空走匿名额度（每日 5 次），填写后每日 20 次。不影响主价格源，只用于调价预测。 |
| **省份** | 下拉选择省份（31 个省级行政区），提交时校验该省能取到价格。 |

- 一个条目可挂多个省份：首个省份在配置时添加，后续在选项中追加。

#### 每日内容

| 字段 | 说明 |
| :--- | :--- |
| **接入名称** | 选填，作为设备名称，留空用服务名。 |
| **ApiZero KEY（选填）** | 留空走 xxapi 免密主源；填写后优先 ApiZero。「历史上的今天」强制需要 KEY，其余三项无需 KEY。填写前须在 ApiZero 控制台开通 `hitokoto` / `shici` / `soul-soup` / `history-today` 四个接口——未开通时 KEY 虽能通过鉴权，接口仍返回「请先开通」，集成会自动降级到 xxapi，来源不会切换。 |

- 固定一条目一设备、4 个传感器（每日一言 / 每日诗词 / 毒鸡汤 / 历史上的今天），无户号 / 省份。
- 有 KEY 走 ApiZero 主源时按分类 TTL 限频（避免诗词 / 毒鸡汤日额度 20 次超额）：每日一言 10 分钟、每日诗词 / 毒鸡汤 1 小时、历史上的今天随轮询；未到期沿用上次值。无 KEY 走 xxapi 免密主源不限频。

#### 灾害预警

| 字段 | 说明 |
| :--- | :--- |
| **接入名称** | 选填，作为设备名称，留空用服务名。 |
| **地区** | 下拉选择区域作为数据源预选，提交后在下一步细选具体数据源。 |

- 两步提交：先选地区预勾选，再细选数据源（至少选一项）；只订阅勾选源的告警，未选源不参与更新。
- 固定一条目一设备、3 个传感器（地震预警 / 地震情报 / 海啸预警），无户号 / 省份。

### 步骤 3：选项设置 (UI Options)

在 **设置 > 设备与服务 > 生活信息** 对应条目上点击 **配置**，进入选项菜单：

| 菜单项 | 适用服务 | 说明 |
| :--- | :--- | :--- |
| **添加户号 / 添加省份** | 燃气 / 油价 | 追加一个设备，填写方式与配置向导二级界面相同，校验后追加。 |
| **移除户号 / 移除省份** | 燃气 / 油价 | 移除一个设备；**至少保留一个**，最后一个不可删。 |
| **编辑接入信息** | 四者 | 两步：先选接入项，再改信息。燃气可改接入名称与地区（户号锁定）；油价、每日内容、灾害预警只能改接入名称（省份 / key / 地区与数据源锁定）。 |
| **ApiZero KEY** | 油价 / 每日内容 | 设置 / 清空密钥，留空回落匿名额度，保存后立即生效。 |
| **关注范围** | 灾害预警 | 两级：先选区域预勾选，再细选数据源，仅勾选的源参与更新。 |
| **轮询间隔** | 四者 | 燃气可选 1/3/6/12 小时（默认 6）；油价可选 6/12/24 小时（默认 12）；每日内容可选 10/20/30/60/120/240 分钟（默认 10）；灾害预警可选 5/15/30/60 分钟（默认 5）。保存自动重载，无需重启 HA。 |

> **重复添加服务不会新建条目**：服务级唯一，要加第二个户号 / 省份必须走条目的「配置 → 添加户号 / 添加省份」。每日内容与灾害预警为一条目一设备，无户号 / 省份可加。

## 🔄 数据刷新与容错

| 服务 | 刷新机制 | 失败处理 |
| :--- | :--- | :--- |
| **昆仑燃气** | 按条目设置的小时级间隔轮询；多户号请求做相位打散，避免并发齐发。 | 失败在 24 小时 TTL 内沿用缓存（属性带缓存时间），过期仍失败抛更新失败、实体转不可用，下周期自动重试。 |
| **油价信息** | 按小时级间隔轮询；价格走 xxapi → ApiZero → 网页三级回补。 | 三源全失败（无任何省份拿到有效价格）才整体失败、实体转不可用；单省缺失按空数据处理。调价信息独立 24 小时缓存，失败沿用旧值，不拖垮价格实体。 |
| **每日内容** | 按分钟级轮询（默认 10 分钟）；有 KEY 走 ApiZero 时按分类 TTL 限频（一言 10 分钟 / 诗词·毒鸡汤 1 小时 / 历史随轮询），未到期沿用上次值；夜间 0–5 点静默不取数，天亮恢复。 | 单实体全源失败仅该实体 unknown，四个全失败才整体不可用；按实体分键持久化，失败 24 小时 TTL 内沿用，跨重启恢复。ApiZero 超额自动降级 xxapi 兜底。 |
| **灾害预警** | 启动 `snapshot` 快照初始化，随后单条 WS 全量增量为主、HTTP 5 分钟轮询兜底；断线重连补快照，心跳原样回显。 | 取数失败 1 小时 TTL 内沿用缓存；31 源按三类分流，仅勾选的源参与更新；同一事件按报次覆盖，`recv_time` 防乱序。 |

- 数据不可达时实体转为不可用是 HA 规范行为，恢复后下个周期自动重试，无需手动干预。

## 💡 常见问题 (FAQ)

#### Q: 为什么再次添加同一服务被直接拒绝？
#### A: 服务级唯一设计——每个服务只允许一个条目。加第二个户号 / 省份请进已有条目的 **配置 → 添加户号 / 添加省份**，而不是重新添加集成。

#### Q: 燃气户号校验失败（cannot_connect / 户号不正确）怎么办？
#### A: 确认户号与地区匹配（地区取省份，不是城市），接口返回的用户号必须与填入户号一致。若使用代理或网络受限，请先排查 HA 到 `bol.grs.petrochina.com.cn` 的连通性。

#### Q: 油价 ApiZero KEY 必须填吗？
#### A: 不必须。留空走匿名额度（每日 5 次），填写后每日 20 次。主价格源 xxapi 无需 KEY，KEY 只影响调价预测的获取额度。

#### Q: 油价实体的价格与加油站标价不一致？
#### A: 主数据源为省级成品油价格；网页兜底源为加油站零售参考价。两者在多数省份一致，个别地区可能存在差异，以官方公布价格为准。

#### Q: 每日内容夜间为什么不更新？
#### A: 0–5 点为静默时段，不请求上游，实体沿用天亮前的最后一次读数；5 点后自动恢复刷新。这是为了减少无意义的夜间请求（也让 ApiZero 匿名额度不超额），不是故障。若夜间 HA 刚启动且无缓存，会取数一次避免实体不可用。

#### Q: 「历史上的今天」为什么不可用？
#### A: 该实体强制需要 ApiZero KEY：无 KEY 时其余三项走 xxapi 正常，唯独历史今日返回 unknown。在条目的「配置 → ApiZero KEY」填入密钥即可启用；填 KEY 前还需在 ApiZero 控制台开通对应接口（见下条）。

#### Q: 填了 ApiZero KEY，为什么来源没切换到 ApiZero？
#### A: KEY 本身有效还不够——须在 ApiZero 控制台开通 `hitokoto` / `shici` / `soul-soup` / `history-today` 四个接口。未开通时接口返回 403「请先开通对应接口」，集成会按设计自动降级到 xxapi，因此实体来源仍显示 xxapi。判断方法：在 ApiZero 控制台逐一开通这四个接口（开通不收费、不冻结余额），保存后重载集成即可切换。

#### Q: 灾害预警为何没有某类数据？
#### A: 只订阅「关注范围」里勾选的数据源。若某类（地震预警 / 地震情报 / 海啸预警）无数据，进条目「配置 → 关注范围」补选该类数据源即可。

#### Q: 灾害预警信息为何与官方略有差异？
#### A: 灾害预警聚合多方公开源，同一事件按报次覆盖更新，可能与官方发布存在时间或数值差异。请以官方发布为准，本集成仅供生活信息参考。

#### Q: 实体间歇性「不可用」？
#### A: 多为上游接口抖动或额度耗尽。检查：燃气看户号/地区与缓存是否过期；油价看 xxapi 是否可达、ApiZero 匿名额度是否用尽（可填 KEY 提升额度）。恢复后下个周期自动重试。

#### Q: 为什么燃气地址字段在属性里而不单独建实体？
#### A: 户名、地址、绑定手机号等是用户档案信息，变化极低频，作为余额实体的属性展示更合适，避免实体列表冗余。
